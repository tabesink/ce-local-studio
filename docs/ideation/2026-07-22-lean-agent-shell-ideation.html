Lean Agent Shell — alternate designs for Context Engine

Topic

Focus
Alternate system shape as a lean agent shell that keeps current base functionality (governed multi-domain RAG, Evidence, SSE turns, authz) and makes chat history first-class — without Local Studio fat-agent sprawl.
Mode
repo-grounded

Grounding Context

Codebase context. Context Engine is a docs-first governed RAG workstation (FastAPI + Next BFF + PostgreSQL). The real spine is already conversations / conversation_turns, TurnOrchestrator, Evidence mapping, and composer refs — not a plugin runtime. app/server/tools/ is a domain runtime controller, not agent tools. Specs reject Pi tools, filesystem automation, and browser-selected runtimes. As-built gaps: P7 chat orchestration unfinished, pilot SSE vs contract drift, three-region workbench incomplete.

External context. High-value prior art converges on bounded plan–retrieve–answer (Azure agentic retrieval), sparse/fixed graphs over open ReAct, and strict separation of thread history vs corpus RAG memory namespaces. Market “knowledge layers for agents” package retrieval-as-tool with citations; CE’s opportunity is those benefits without a generic tool registry. Analogies that held: query planner, email thread + case file, compiler pipeline.

#1

Sealed Turn Pipeline Shell

orchestration-shell Conf High Cx Medium

Treat the lean “agent shell” as a fixed, server-owned turn pipeline viewport — not a tool host. The product surface projects the contracted SSE graph (turn.accepted → route.selected → retrieval.started → evidence.delta* → answer.delta* → turn.completed) with one live/resume/replay reducer. TurnOrchestrator plus idempotent terminal replay is the agent; there is no tool registry, approval queue, or separate agent-runtime process.

Basis direct: production-adaptation “a separate agent runtime is not required”; PRD bounded plan/retrieval/repair; SSE legal sequences; components one-reducer rule. external: Azure plan–retrieve–answer; compiler-pipeline / ATC clearance-strip analogies.

Rationale. Gives engineering and product a shared name for “agent-like” without inviting Local Studio sprawl, and makes finishing P7 SSE contract parity the shell’s acceptance gate.

Downsides. Feels less “agentic” to stakeholders who expect tool loops; requires killing pilot stage/token/done emissions and finishing frontend reducer work.

#2

Case-File Carry-Forward

chat-history-memory Conf High Cx Medium

Make chat history actionable working memory without an agent memory store: prior turns contribute re-resolvable slots (accepted Evidence/wiki/template refs, last domain selection metadata) via composer-refs:discover / _discover_evidence. Follow-ups inherit governed chips with TTL and one-use rules — not stuffed prior assistant answers or a second vector memory competing with domain RAG.

Basis direct: prior synthesis uses user questions only; composer-ref discovery against completed turns; never persist assembled prompts; redaction preserves user question. external: LangChain thread history ≠ corpus memory namespaces; film continuity binder analogy.

Rationale. Best answer to “incorporate chat history” inside CE invariants: the thread becomes a case file members can re-cite, compounding Evidence already paid for.

Downsides. UX must make carry-forward explicit (chips) so members know what is attached; expiry still rejects stale tokens (M-09).

#3

Case-File Workbench

workbench-ux Conf High Cx Medium

Lock the human-facing shell as a case file, not an agent IDE: discovery rail = conversation docket; center = chronological turn ledger (history primary); inspector = working papers (Evidence / Refs / Source / Wiki) for the selected turn. Adapt Local Studio shell geometry only; strip model picker, terminal, tool approval.

Basis direct: normative three-region chat-and-evidence-workbench; ui-parity forbids agent-only controls; as-built still timeline + single Evidence aside; F-009/F-012 drift must be resolved once.

Rationale. History is only first-class if discoverable and inspectable; this is the product shape that makes ideas #1 and #2 legible to members.

Downsides. Requires one authoritative layout decision and finishing incomplete three-region UI — not a backend-only win.

#4

Closed Capability Manifest

trust-anti-sprawl Conf High Cx Low

Define the lean shell as a closed verb set: classify, retrieve, synthesize, replay, cancel, redact (optionally project_evidence / grounded_refuse as retrieval subtypes). Any proposed “agent feature” must name which verb it extends; UI that implies an open tool palette stays forbidden. BFF airlock rules stay mandatory.

Basis direct: AGENTS out-of-scope plugins/tools; ui-parity agent-control ban; production-adaptation reject matrix; turn lifecycle counters. external: IBM agent-sprawl risks; cleanroom airlock analogy.

Rationale. Turns “we’re not an agent platform” from prose into a merge gate — the cheapest structural defense while still allowing agent-shell language.

Downsides. Manifest must be maintained; pressure to add “just one tool” will reappear as “just one verb.”

#5

Inspectable Grounded Outcomes

retrieval-grounding Conf High Cx Medium

Design the shell around non-prose success paths: no_grounded_context and evidence_only are first-class terminals with inspector projections (what was searched / what exhibits landed), not empty assistant bubbles. Domain answers never fall back to general model knowledge.

Basis direct: contracted stopReasons; evidence service returns empty → no synthesis; interaction cases for grounded refusal; pharmacy formulary / closed-stack call-slip analogies.

Rationale. Lean agency = retrieval discipline. Trust grows when refusal is legible.

Downsides. Copy and empty-states need design care so refusal doesn’t feel like outage.

#6

Visible Continuity Budget

chat-history-memory Conf Med Cx Medium

Expose the server’s history window as product truth: which prior user questions are in-scope for synthesis (MAX_PRIOR_USER_QUESTIONS = 4), which fell off, and how composer refs consume assembly budget — without persisting assembled prompts.

Basis direct: hard-coded prior-question cap and assembly caps in chat_turns/prompt_assembly. Verifier note: public budget DTO today covers op counters, not prior-Q scope — this idea requires a contract addition.

Rationale. Fixes the #1 history friction (“it forgot”) without inventing agent memory.

Downsides. Needs approved DTO/SSE fields; weak until contracts move.

#7

Single-Shot Grounded Repair

retrieval-grounding Conf Med Cx Medium

Before terminal no_grounded_context, allow exactly one server-owned repair (rephrase / alternate retrieval intent) tracked by repair_attempt_count, then refuse. Still no general-knowledge fallback and no open ReAct loop.

Basis direct: PRD names bounded repair; schema/SSE reserve repair counters. Verifier note: code currently writes 0; P7-03 NOT_STARTED — forward-looking within PRD, not as-built.

Rationale. Raises grounded hit rate while keeping the sealed pipeline lean.

Downsides. Needs a contracted repair algorithm; easy to balloon into multi-hop agency if bounds slip.
